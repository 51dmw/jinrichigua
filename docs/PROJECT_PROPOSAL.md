## 二、项目背景

娱乐资讯、社会热点与网络事件类内容长期具备高频、高量的搜索需求，且长尾关键词分布极广——
单个热点事件可衍生出"是谁 / 怎么回事 / 后续 / 回应 / 时间线"等一整簇搜索意图。这类内容
更新即时性强、生命周期短，恰好与搜索引擎对新闻类内容的抓取偏好（Google News、
Discover、IndexNow 即时推送）形成匹配，是自然流量增长弹性较大的品类。

公司已具备完整的前后端自研能力，无需依赖第三方建站产品或采购成品源码，可以从内容模型、
URL 结构、结构化数据到发布流程按 SEO 规范一次性设计到位——这是采购成品站难以做到的。

同时，此类内容存在明确的合规边界（涉及真实人物的名誉权、未经核实的传闻、时政敏感内容），
必须在系统层面而非人工自觉层面建立管控机制。这也是自研而非采购的一个决定性理由。

---

## 三、项目目标

1. 建成一个以热点资讯、网络事件、娱乐八卦为核心的多频道资讯平台。
2. 网站架构满足搜索引擎收录与排名的工程要求：规范化 URL、分层 sitemap、
   结构化数据、内链闭环、页面性能（CLS 趋零、零 Web 字体）。
3. 建立支持高频发布的内容生产与审核体系，具备日均数十篇的稳定产出能力。
4. 建立系统级内容合规管控：先审后发、敏感词过滤、发布权限分离。
5. 预留广告与联盟推广的承载能力，为后续商业化提供流量与版位基础。

**面向的搜索引擎**：Google / Bing / Yandex。**不针对百度做优化**——这是明确的取舍，
百度对新站与非备案内容站的收录门槛与本项目的产出节奏不匹配。

## 四、项目建设内容

### 1. 首页

首页区块不写死在代码里，由后台单类型「首页编排」驱动区块顺序、版式与取数规则，
运营可自行调整栏目而无需发版。

- 头条与热门推荐区块
- 频道导航（11 个频道）
- 最新资讯流
- 吃瓜热榜（按真实 PV 排序）
- 精选标签（按标签下最热文章的点击数排序）
- 卡片五种版式：大图 / 左文右图 / 三图 / 纯文字 / 左图右标题

### 2. 内容频道

线上实际运行 11 个频道：

| 频道 | 路径 | 频道 | 路径 |
|---|---|---|---|
| 明星娱乐 | `/star` | 情感婚恋 | `/love` |
| 网红达人 | `/influencer` | 体育吃瓜 | `/sports` |
| 吃瓜视频 | `/video` | 校园热议 | `/campus` |
| 社会大瓜 | `/society` | 海外吃瓜 | `/oversea` |
| 爆料内幕 | `/inside` | 历史旧瓜 | `/history` |
| 黑料档案 | `/dirt` | | |

频道页支持翻页（20 条/页），**翻页限深 5 页**——更深的历史内容通过归档页与 sitemap
承接。这是有意的收录策略，不是功能缺失：避免深层分页页面稀释抓取预算。

### 3. 内容详情页

- 图文正文（Markdown 渲染，支持标题层级、列表、引用、表格、FAQ 结构）
- 标签系统（多对多，标签页为独立聚合页）
- 上下篇导航
- 相关文章推荐——**按共享标签相关度计算**，而非同频道简单堆叠
- 面包屑（含 BreadcrumbList 结构化数据）
- 作者署名与作者主页
- PV 统计（原子自增，不依赖第三方脚本）
- 分享按钮
- 评论：**已实现且已上线**，任何人可评论、先审后发

### 4. 聚合与工具页

- 标签页 `/tag/[slug]`、作者页 `/author/[slug]`
- 站内搜索 `/search`（`noindex`，仅服务用户不参与收录）
- 吃瓜热榜 `/hot`
- 文章归档 `/archive/[year]/[month]`——老内容的内链枢纽
- 信息页 `/info/[slug]`（关于我们、免责声明、隐私政策等，线上 20 篇）

### 5. 后台管理系统

基于 Strapi 5 自建，后台界面已全量汉化。内容模型 10 类：

| 模型 | 说明 |
|---|---|
| 文章 | 含审核状态、业务发布时间、SEO 组件、PV |
| 频道 | 含导航开关、排序、频道 SEO 描述 |
| 标签 | slug 由拼音自动生成并去重 |
| 作者 | 29 位，含身份角色标签（E-E-A-T 支撑） |
| 评论 | 先审后发 |
| 广告位 | 19 个全站版位 |
| 信息页 | 独立单页 |
| 敏感词 | 驱动发布拦截 |
| 首页编排 | 单类型，驱动首页区块 |
| 站点设置 | 单类型，站名/Logo/备案号等全局配置 |

**权限体系**：除内置 Super Admin 外，自动创建「编辑（可增改文章，无发布权）」与
「审核（可发布）」两个角色，从权限层面强制审核与发布分离。

**审核流**：草稿 → 待审（pending）→ 审核通过（approved）→ 发布。
系统内置**发布守卫**：`reviewState != approved` 的文章禁止发布，该守卫在后台界面、
REST API、定时任务三条路径上全部生效，无法绕过。

### 6. 内容生产管线（超出常规资讯站的部分）

`scripts/hot-sync/` 是本项目的内容供给核心，也是"高频发布"目标的实现方式：

```
五路热榜/新闻流同步  →  LLM 选题（过滤时政敏感、合并跨源同事件）
   →  LLM 二次创作成文  →  敏感词过滤  →  Strapi REST 写入
   →  审核通过后发布  →  触发 ISR 重建 + IndexNow 推送
```

- 采集源：微博、百度、抖音、今日头条、知乎五个热榜，外加两路影视娱乐新闻流。
  **只取标题作为选题线索，不抓取任何站点正文**。
- 反雷同机制：内置 13 种写作体裁，按频道亲和度轮换且不重复使用近期用过的体裁；
  并将最近 20 篇的标题与开头作为"已用写法"注入禁令，防止模型收敛出固定套路。
- 生成后端可插拔（当前默认走本机 Claude 订阅），不锁死单一供应商。
- 写入**只经 Strapi REST API**，不直连数据库——保证审核流、敏感词、lifecycle 全部生效。
- 由 PM2 定时拉起，每 2 小时一轮，另有一路存量内容修复任务错峰运行。

## 五、技术方案

### 整体架构

前后端解耦，数据单向流动：**写入只经 Strapi，前台只读已发布内容并静态化，不直连数据库**。

```
浏览器
 └─ Cloudflare（DNS / CDN / WAF）
      └─ VPS Nginx :443
           ├─ tobaoliao.com    → PM2 进程 jrcg-web (Next.js, 127.0.0.1:3100)
           └─ cms.sibian.xyz   → Docker 内 Strapi (127.0.0.1:1337)
                                    ├─ PostgreSQL 16
                                    └─ Redis 7
     媒体 → Cloudflare R2（img.sibian.xyz，配防盗链 WAF，白名单含搜索引擎爬虫）
```

### 选型

| 层 | 选型 | 选择理由 |
|---|---|---|
| 前台 | Next.js 15 App Router · React 19 · TypeScript strict · Tailwind 3 | SSG + 按需 ISR，兼顾首屏性能与内容时效 |
| CMS | Strapi 5.7 | 内容建模灵活、RBAC 完备、lifecycle 钩子可承载审核流与发布联动 |
| 数据库 | PostgreSQL 16 | 生产禁用 SQLite（写入并发与备份可靠性） |
| 缓存 | Redis 7 | Strapi 会话与队列 |
| 媒体存储 | Cloudflare R2（S3 兼容 provider） | 与 CDN 同源、出网流量零费用 |
| 运行时 | Node.js 20 LTS · pnpm workspaces | monorepo，`packages/shared` 存放前后台共享类型，保证类型单一事实来源 |
| 部署 | CMS → Docker Compose；前台 → PM2 + Nginx | 同机部署，Cloudflare 只做 DNS/CDN/WAF，不承载运行时 |

### SEO 工程实现

这部分是本项目相对普通资讯站的主要工程投入，落地项包括：

- **结构化数据**：NewsArticle / NewsMediaOrganization / WebSite / BreadcrumbList /
  ItemList / Person / SpeakableSpecification 七类 JSON-LD。
- **索引通道**：分层 sitemap（索引 + 频道 / 标签 / 作者 / 文章分片）、
  Google 新闻 sitemap、RSS、Yandex Turbo RSS、`llms.txt`。
- **即时收录**：文章发布触发 IndexNow 推送 Bing / Yandex，同时调用前台
  `/api/revalidate` 做按需 ISR 重建。
- **规范化**：canonical、hreflang、URL 小写与去尾斜杠、空聚合页返回 404 不占收录。
- **性能**：简体中文系统字体栈（零 Web 字体）、AVIF/WebP、广告位按标准尺寸预留宽高比，
  CLS 趋近于 0。

### 发版机制

前台发版走 `scripts/deploy-web.sh`：先构建到临时目录，校验产物完整后才**原子切换** `.next`
并重启 PM2，任一步失败即中止，线上运行版本不受影响；上一版保留可即时回滚。
这条流程解决的是"构建失败直接把线上打成 502"的问题。

## 六、开发原则

1. **不使用未经审核的第三方项目代码**，不抓取、不复制任何站点的文本、图片或数据。
   版式仅参考资讯门户移动版的**结构**。
2. **写入只经 Strapi**，任何脚本与外部程序都不得直连数据库——否则审核流与敏感词形同虚设。
3. **TypeScript strict**，共享类型集中在 `packages/shared`，禁止前后台各写一份。
4. **先审后发 + 敏感词过滤**为系统级强约束，不依赖人工自觉。
5. **CORS 锁定域名**，生产禁用 SQLite，机密一律不入库。
6. 改动控制在可回滚粒度，发版走原子切换脚本。

## 十、项目风险及应对措施

| 风险 | 等级 | 应对措施 |
|---|---|---|
| **内容合规风险**（涉及真实人物的名誉权、未核实传闻、时政敏感） | 高 | 三道闸：选题阶段 LLM 过滤时政敏感；成文后敏感词库拦截；发布前人工审核且发布权与编辑权分离。生成规则明令禁止编造具体数字、时间与当事人表态 |
| **单机单点**——前台、后台、数据库同在一台 VPS，且备份无异地副本 | 高 | 已有每日热备与完整性校验；**待办：备份异地同步**。这是当前最大的架构性风险，建议二期解决 |
| 搜索引擎算法变化 | 中 | SEO 规则集中沉淀在 `docs/seo-training/`，规则与落地点一一对应，算法调整时可定位修改而非全站返工 |
| **生成内容同质化**导致质量评级下降 | 中 | 13 种体裁轮换 + 近期写法反注入禁令；另有存量内容修复任务定期回扫改写 |
| CMS 无 CI，改动需手工重建镜像才生效 | 中 | 已在 `CLAUDE.md` 与 `deploy/OPS.md` 中列为首要注意事项；二期补 CI |
| 内容更新频率不足 | 低 | 已由定时管线保障基础产出，人工只承担审核 |
| 系统性能问题 | 低 | SSG + 按需 ISR，正常访问不打到数据库；媒体走 R2 + CDN |
| 开发延期 | 低 | 分阶段验收，每阶段产出可独立验证 |
